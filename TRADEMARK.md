# Using the Quaill Records name

The checker is open source under Apache-2.0. The name "Quaill Records" and the Quaill mark are not part of that license; they belong to Quaill LLC. This page says how the name may be used so that a report never turns into a safety claim it did not make.

## Allowed

- "Checks against Quaill Records spec v0.0.2" or "meets Quaill Records checks (profile `quaill-control` v0.0.2)", with the version.
- "Recorded with a Quaill Records connector" for a recorder that emits the three channels.
- Quoting a report verbatim, with its file hash and tool version.
- Saying your product is "compatible with" or "tested against" the Quaill Records checker.
- Forking the code under Apache-2.0 under a different name.

## Not allowed

- "Quaill-certified", "Quaill-verified", "Quaill-approved", "Quaill-compliant", or any wording that presents a PASS as a certification, approval, or safety judgment.
- "Safe", "secure", "tamper-proof", "court-proof", "EU AI Act compliant", or "Machinery Regulation compliant" in connection with the name. The checker grades a file against a rule set; it does not judge a robot, a company, or legal compliance.
- Using the name or mark as the name of a modified checker, so that a changed tool is mistaken for this one.
- A badge or seal that does not state the spec version and link to the public method.

## Why this is strict

A PASS means: this file meets these checks, as of this version, for the checks that were assessable. A robot that passes can still hurt someone; a maker that passes can still have a recorder that lied when it wrote. The first time a "Quaill-certified" robot is in a headline, the name stops meaning anything. Keeping the name narrow keeps the report worth something.
